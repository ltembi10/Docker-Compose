 Analysis of My CI/CD Pipeline Experience

Using automated testing in my CI/CD pipeline improves software 
reliability because it checks the application every time changes 
are pushed to GitHub. Instead of relying only on manual testing, 
the pipeline automatically runs tests to make sure the backend and 
frontend are working correctly. Manual testing can take more time, 
and a person might forget to check something. Automated testing makes 
the process more consistent and helps find problems earlier, before 
they affect users.
One important benefit I observed was how the pipeline handled a 
failing test. I intentionally changed the expected health status 
in one of my backend tests from "healthy" to "unhealthy." 
Since this did not match the actual response from the application, 
the test failed. This showed me that the pipeline can catch mistakes 
before the application is deployed. It also prevents a version with 
known problems from reaching users. After correcting the test, 
I could push the changes again and check whether the pipeline 
completed successfully.
GitHub Actions and Jenkins are both useful tools for automating 
software development. GitHub Actions is easy to use because it is 
built into GitHub. It allows developers to create workflows that 
automatically test and deploy their applications. It is especially 
useful for smaller projects and teams that already use GitHub. 
However, it can have limitations with available runner time and 
usage limits depending on the plan.
Jenkins is an open-source automation tool that offers many plugins 
and customization options. It can be used with different platforms 
and development tools. However, Jenkins can be more difficult to set
up and maintain because teams may need to manage their own servers. 
I would choose GitHub Actions for a project like my Recipe Sharing 
application because it is simpler to connect to my GitHub repository.
I would consider Jenkins for a larger project that needs more 
customization and control.
This automation approach can also help larger development teams. 
When several developers work on the same application, automated 
tests can run whenever someone submits new changes. This helps 
identify problems early and reduces the amount of manual work. 
It also helps everyone follow the same testing process, making 
it easier to maintain a reliable application as the project grows.
